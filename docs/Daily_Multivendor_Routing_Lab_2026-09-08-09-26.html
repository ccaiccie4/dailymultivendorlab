Networking Foundations Primer

Universal state chain: originate/learn → policy → advertise/import → RIB selection → recursive resolution → FIB/adjacency/tunnel/label programming → packet forwarding → remote delivery → return-path validation.

Control plane vs data plane

Control-plane protocols decide reachability and intent; the data plane is the FIB, adjacency, label/tunnel or ASIC/kernel state that actually forwards a packet.

RIB, FIB and adjacency

A protocol can learn a route without owning the RIB, and a RIB winner can still fail forwarding if recursive resolution or its final adjacency is incomplete.

Recursive next-hop resolution

A BGP/overlay next hop can resolve through another route repeatedly until forwarding reaches a connected next hop, tunnel, label stack, or fails.

Administrative distance / route preference

This is the platform's cross-protocol preference used when different routing sources offer the same prefix.

Underlay and overlay

The underlay transports infrastructure endpoints. VXLAN, EVPN and MPLS services depend on it but maintain separate control/data-plane state.

VXLAN / VTEP / VNI

VXLAN encapsulates tenant traffic in UDP/IP; VTEPs add/remove encapsulation; the VNI identifies an L2 or L3 service.

EVPN / RD / RT

EVPN uses BGP for endpoint and tenant reachability. RD makes VPN routes unique; RT controls import/export membership.

IRB / anycast gateway

IRB connects bridging to routing. Anycast gateways present one distributed first-hop identity on multiple fabric nodes.

BUM

Broadcast, unknown-unicast and multicast traffic requires replication/multicast handling because one remote unicast destination is not yet known.

LACP / ESI / DF

LACP negotiates physical bundles. EVPN ESI identifies a multihomed Ethernet Segment and DF election coordinates selected BUM forwarding toward it.

VRF / VLAN / trunk

A VRF is an isolated routing table, a VLAN is an L2 broadcast domain, and a trunk carries multiple VLANs.

Redistribution and route policy

Redistribution re-originates routes between protocols; tags/communities/prefix filters preserve origin intent and prevent feedback.

1. Cisco Systems — MPLS LDP Autoconfiguration for OSPF/IS-IS

Exact source: https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/mpls/b-mpls/m_mp-ldp-autoconfig.html

Beginner foundation — terms you need before this lesson

LDP distributes MPLS labels for IGP-reachable prefixes. Normally LDP must be enabled on each participating interface. Autoconfiguration ties LDP enablement to interfaces that already participate in an OSPF or IS-IS process.

Problem and why the feature exists

Large MPLS cores are error-prone when operators enable the IGP on an interface but forget LDP. Autoconfiguration reduces that configuration drift while still allowing exceptions.

Control-plane / state / packet sequence

Enable MPLS/LDP globally → enable mpls ldp autoconfig under the OSPF or IS-IS process → IOS XE enables LDP on eligible IGP interfaces → targeted exclusions use no mpls ldp igp autoconfig → LDP adjacencies exchange labels → LFIB is programmed.

Source-supported configuration and evidence

LDP must be globally enabled first; autoconfiguration can be limited to an OSPF area or IS-IS level. Traffic-engineering tunnel interfaces are not supported. Verify IGP participation and LDP discovery/session state separately.

Failure boundary and troubleshooting implication

A new IGP interface can route IP successfully yet fail MPLS forwarding if excluded from LDP autoconfiguration or if LDP is globally disabled.

2. Cisco Systems — OSPF Sham Links Across MPLS VPN

Exact source: https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_iro-vrf-lite-pe-ce.html

Beginner foundation — terms you need before this lesson

An OSPF backdoor link between sites can be intra-area while the MPLS VPN path appears interarea. A sham link creates a logical intra-area OSPF adjacency across the VPN backbone.

Problem and why the feature exists

Without a sham link, OSPF route-type preference can push traffic onto a lower-capacity backdoor even when the MPLS backbone should be primary.

Control-plane / state / packet sequence

MP-BGP carries VPN reachability → backdoor intra-area route may win → sham-link endpoints form OSPF adjacency across the VRF/VPN → LSAs flood across the logical link → sham-link cost competes with the backdoor cost.

Source-supported configuration and evidence

Cisco documents area ... sham-link source destination [cost]; endpoints must be reachable inside the VRF.

3. Cisco Systems — BGP Link Bandwidth Extended Community

Exact source: https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_irg-link-band-0.html

Beginner foundation — terms you need before this lesson

BGP Link Bandwidth attaches exit-link capacity as an extended community so otherwise eligible multipaths can receive proportional forwarding weights.

Control-plane / state / packet sequence

Direct eBGP route → neighbor ... dmzlink-bw adds bandwidth metadata → extended community propagates over iBGP → multipath selection retains paths → CEF derives traffic-share weights.

Source-supported configuration and evidence

Cisco requires multipath, CEF, and extended-community propagation. The feature is limited to IPv4/VPNv4 and originates bandwidth only for directly connected eBGP links.

4. Palo Alto Networks — Advanced Routing Engine RIB Filtering

Exact source: https://docs.paloaltonetworks.com/ngfw/networking/advanced-routing/enable-advanced-routing

Beginner foundation — terms you need before this lesson

RIB filtering decides whether matched routes enter the logical router's route-selection database; it is different from filtering a protocol's export to a neighbor.

Control-plane / state / packet sequence

Route received/created → route-map RIB filter evaluates → permitted candidate enters RIB → winner programs forwarding; denied candidate never competes locally.

Failure boundary and troubleshooting implication

An export filter can stop advertisements while the route remains locally active. A RIB filter can remove local candidacy entirely.

5. Palo Alto Networks — PIM RPF Lookup Modes: MRIB, URIB, MRIB-then-URIB

Exact source: https://docs.paloaltonetworks.com/ngfw/networking/advanced-routing/configure-ipv4-multicast

Beginner foundation — terms you need before this lesson

Reverse-path forwarding chooses the upstream interface toward the multicast source/RP. PAN-OS can consult MRIB, URIB, or MRIB then fall back to URIB.

Failure boundary and troubleshooting implication

A healthy unicast route does not help when MRIB-only is selected and MRIB lacks the source. In MRIB-then-URIB mode the same topology may succeed.

6. Palo Alto Networks — Enforce First AS for eBGP

Exact source: https://docs.paloaltonetworks.com/ngfw/help/12-1/network/network-virtual-routers/bgp/bgp-advanced-tab

Beginner foundation — terms you need before this lesson

First-AS enforcement checks whether the first AS_PATH segment matches the configured directly connected eBGP peer AS.

Failure boundary and troubleshooting implication

PAN-OS enables this check by default; route-server sessions can legitimately violate the ordinary first-AS expectation and therefore require deliberate design.

7. Fortinet — OSPF distribute-list-in Local RIB Filtering

Exact source: https://docs.fortinet.com/document/fortigate/7.6.6/administration-guide/315077/access-lists

Beginner foundation — terms you need before this lesson

FortiGate can keep an OSPF LSA in the LSDB while preventing the resulting prefix from entering the local routing table using distribute-list-in.

Failure boundary and troubleshooting implication

LSDB presence plus RIB absence is the expected signature of local installation filtering, not proof that the filter failed.

8. Fortinet — OSPF Area Filter Lists vs Local Distribute Lists

Exact source: https://docs.fortinet.com/document/fortigate/7.6.6/cli-reference/103419153/config-router-ospf

Beginner foundation — terms you need before this lesson

An area filter-list acts at an ABR boundary on inter-area summaries; a local distribute-list-in acts on one router's local installation.

Source-supported configuration and evidence

FortiOS exposes config area → config filter-list → direction in|out → list. Verify Type-3 summary visibility across the boundary.

9. Fortinet — PIM Join/Prune and Hello Timer Tuning

Exact source: https://docs.fortinet.com/document/fortigate/7.6.6/administration-guide/896987/multicast-routing-and-pim-support

Beginner foundation — terms you need before this lesson

PIM Hello maintains neighbor adjacency; Join/Prune messages refresh multicast tree membership. They are separate state machines.

Failure boundary and troubleshooting implication

Changing Join/Prune interval cannot repair a missing neighbor, while healthy Hellos do not prove source/group tree refresh.

10. Arista Networks — ARP/ND Learning from Bridged EVPN Traffic

Exact source: https://www.arista.com/en/support/toi/tag/arp

Beginner foundation — terms you need before this lesson

Newer EOS behavior can snoop ARP/ND frames that are only being bridged, learning endpoint IP/MAC bindings even when the packet is not addressed to the SVI.

Failure boundary and troubleshooting implication

Proxy/suppression correctness now depends on freshness of these snooped bindings; stale state after a host move can misdirect replies.

11. Arista Networks — BFD Tracking for VXLAN Static Routes

Exact source: https://www.arista.com/en/support/toi/tag/bfd

Beginner foundation — terms you need before this lesson

BFD adds a liveness dependency to a VXLAN static route so route installation can follow actual endpoint reachability rather than only recursive IP resolution.

Failure boundary and troubleshooting implication

A tracked static route can disappear while the peer IP still pings because BFD liveness is a stronger install condition than plain route resolution.

12. Arista Networks — Auto-Derived EVPN Route Targets for L3 VRFs

Exact source: https://www.arista.com/en/support/toi/tag/evpn

Beginner foundation — terms you need before this lesson

EOS 4.35.1F+ can derive L3-VRF route targets from VNI information, reducing manual RT configuration.

Failure boundary and troubleshooting implication

VNI inconsistency can become an RT import mismatch automatically, so tenant VNI alignment is now part of RT troubleshooting.

13. FRRouting — Conditional BGP Default-Originate with Route Map

Exact source: https://docs.frrouting.org/en/stable-10.7/bgp.html

Beginner foundation — terms you need before this lesson

FRR does not advertise default merely because 0/0 exists locally; neighbor ... default-originate explicitly creates the advertisement and a route map can make it conditional.

Failure boundary and troubleshooting implication

A BGP session can stay Established while the default is withdrawn because the condition route disappeared.

14. FRRouting — BGP suppress-fib-pending

Exact source: https://docs.frrouting.org/en/latest/bgp.html

Beginner foundation — terms you need before this lesson

This feature delays advertising newly peer-learned routes until zebra/dataplane confirms FIB installation.

Failure boundary and troubleshooting implication

It protects initial route advertisement, but FRR documents that later dataplane deletion of an already advertised route does not automatically guarantee withdrawal.

15. FRRouting — BGP advertisement-delay vs update-delay

Exact source: https://docs.frrouting.org/en/stable-10.2/bgp.html

Beginner foundation — terms you need before this lesson

advertisement-delay lets local best-path/FIB progress while delaying outbound UPDATEs; update-delay can defer broader BGP convergence processing.

Failure boundary and troubleshooting implication

When both are configured, outbound advertisements release at the later gating condition.

16. Juniper Networks — BGP advertise-peer-as and Same-AS eBGP Suppression

Exact source: https://www.juniper.net/documentation/us/en/software/junos/cli-reference/topics/ref/statement/advertise-peer-as-edit-protocols-bgp.html

Beginner foundation — terms you need before this lesson

Junos suppresses readvertisement of a route from one eBGP peer to another peer in the same AS as the origin. advertise-peer-as overrides the sender-side suppression.

Failure boundary and troubleshooting implication

The receiving site may still reject the route because its own AS appears in AS_PATH, requiring separately controlled loop acceptance.

17. Juniper Networks — IS-IS IPv6-Only Mode with no-ipv4-routing

Exact source: https://www.juniper.net/documentation/us/en/software/junos/cli-reference/topics/ref/statement/no-ipv4-routing-edit-protocols-isis.html

Beginner foundation — terms you need before this lesson

The knob removes IPv4 NLPID/address/prefix advertisement and IPv4 route calculation while leaving IS-IS operating for IPv6.

Failure boundary and troubleshooting implication

Trace logs can still show IPv4 routes being examined and rejected during export scans; that is not evidence IPv4 IS-IS routing remains enabled.

18. Juniper Networks — BGP keep all vs keep none

Exact source: https://www.juniper.net/documentation/us/en/software/junos/cli-reference/topics/ref/statement/keep-edit-protocols-bgp.html

Beginner foundation — terms you need before this lesson

keep-all retains rejected BGP routes for later reevaluation; keep-none discards them and reduces memory but may require the peer to resend routes after policy changes.

19. Aruba/HPE — DHCP Relay Helper in a Nondefault VRF

Exact source: https://www.arubanetworks.com/techdocs/AOS-CX/10.13/PDF/ip_services_8400.pdf

Beginner foundation — terms you need before this lesson

When ip helper-address specifies a VRF, AOS-CX requires an appropriate DHCP relay source using ip source-interface.

Failure boundary and troubleshooting implication

Server reachability in the default VRF proves nothing about the relay path in the client VRF.

20. Aruba/HPE — BFD Detection Multiplier and Interface Overrides

Exact source: https://www.arubanetworks.com/techdocs/AOS-CX/10.13/PDF/high_availability.pdf

Beginner foundation — terms you need before this lesson

BFD detection time derives from negotiated interval constraints and a detection multiplier. AOS-CX supports interface-level timing and protocol-specific overrides.

Failure boundary and troubleshooting implication

A configured BFD session does not prove OSPF/PIM is subscribed; per-interface protocol BFD can be disabled independently.

21. Aruba/HPE — EVPN Route Maps: match VNI and Continue

Exact source: https://www.arubanetworks.com/techdocs/AOS-CX/10.13/PDF/vxlan.pdf

Beginner foundation — terms you need before this lesson

AOS-CX EVPN route maps can match VNI and use Continue for multi-stage route-policy evaluation.

Failure boundary and troubleshooting implication

Changing EVPN next hop also has router-MAC consistency implications; a reachable VTEP IP alone is not enough to guarantee correct forwarding.
