Networking Foundations Primer

Universal state chain: learn/originate → policy → advertise/import → RIB selection → recursive next-hop resolution → FIB/adjacency/tunnel/label programming → packet forwarding → remote delivery → return-path proof.

Control plane vs data plane: control protocols create state; the data plane actually forwards. RIB vs FIB: the RIB selects a route; the FIB is the forwarding-ready result. Underlay vs overlay: VXLAN/EVPN/MPLS services depend on transport reachability. RD/RT: RD makes VPN routes unique, RT controls import/export. IRB/anycast: bridge and route locally with a common first-hop identity. BUM: broadcast, unknown-unicast and multicast require replication. Redistribution: re-originates routes across protocols and therefore needs provenance policy. LACP/multichassis/ESI/DF: link aggregation and standardized multi-attachment require separate state checks. VRF/VLAN/trunk: isolated L3 table, L2 broadcast domain, and multi-VLAN link.

1. Cisco — BGP GTSM / TTL Security

Source: https://www.cisco.com/c/en/us/td/docs/iosxr/cisco8000/bgp/bgp-config-cisco8000/r-wrapper-bgp-session-security-mechanisms/c-bgp-ebgp-security-gtsm.html

Beginner foundation — terms you need before this lesson

GTSM validates received IPv4 TTL or IPv6 Hop Limit for eBGP packets. Adjacent peers transmit with the maximum value, making off-path spoofed packets easier to reject.

Why / mechanics / evidence

GTSM protects the BGP control plane before route policy ever sees an UPDATE. Packet arrives → TTL/Hop Limit validation → TCP/BGP FSM → route policy → RIB/FIB. Cisco documents ttl-security and an XR example with ebgp-multihop 255. If ping works but BGP does not establish, capture the actual TTL/Hop Limit and validate both peers' expected hop relationship before changing route attributes.

Lab

Establish loopback eBGP, enable GTSM, change path length, and observe which control-plane boundary fails.

2. Cisco — OSPF Demand Circuit

Source: https://www.cisco.com/c/en/us/support/docs/ip/open-shortest-path-first-ospf/5132-dc.html

Beginner foundation — terms you need before this lesson

Demand circuits suppress recurring OSPF control traffic on costly/on-demand links; DoNotAge behavior prevents routine LSA refresh from continually waking the circuit.

Why / mechanics / evidence

Adjacency/database is established → periodic refresh/hello behavior is suppressed as designed → logical reachability persists. Silence is therefore not automatically an OSPF failure. Verify neighbor/database and demand-circuit state rather than assuming missing periodic packets mean adjacency loss.

Lab

Compare ordinary and demand-circuit OSPF control traffic while topology is stable, then trigger a real topology change.

3. Cisco — LACP Port-Channel Min-Links

Source: https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst3850/software/release/16-8/configuration_guide/lyr2_lyr3/b_168_lyr2_lyr3_3850_cg/b_168_lyr2_lyr3_3850_cg_chapter_011.html

Beginner foundation — terms you need before this lesson

Min-links gates logical port-channel state on the number of actually bundled LACP members.

Why / mechanics / evidence

LACP negotiates → bundled members are counted → min-links threshold determines logical Up/Down → routing/STP above the bundle reacts. port-channel min-links sets the threshold; show etherchannel summary proves bundled/standby members. A four-link bundle dropping after two member failures can be intentional behavior.

Lab

Require three of four members, remove links one at a time, and measure routing adjacency/traffic effects.

4. Palo Alto Networks — BGP Conditional Advertisement

Source: https://docs.paloaltonetworks.com/ngfw/help/11-1/network/network-virtual-routers/bgp/bgp-conditional-adv-tab

Beginner foundation — terms you need before this lesson

Conditional advertisement uses a watched BGP condition plus an advertise filter to announce backup NLRI only when the condition changes.

Why / mechanics / evidence

Loc-RIB condition → non-exist/condition evaluation → alternate advertisement becomes eligible → peer receives backup prefixes. The important distinction is BGP local-RIB state versus global forwarding state. Inspect the watched route and actual advertised routes before changing BGP attributes.

Lab

Withdraw the watched BGP prefix while keeping the neighbor Established and confirm only intended backup routes appear.

5. Palo Alto Networks — BGP Aggregation with Suppress / Advertise Filters

Source: https://docs.paloaltonetworks.com/ngfw/help/10-2/network/network-virtual-routers/bgp/bgp-aggregate-tab

Beginner foundation — terms you need before this lesson

An aggregate summarizes component prefixes; suppress and advertise filters control which specifics remain visible to peers.

Why / mechanics / evidence

Component routes → aggregate formation → optional attribute/AS-set behavior → export suppression/advertisement → remote longest-prefix match. Seeing a summary locally does not prove intended specifics were suppressed. Verify peer advertised-routes.

Lab

Aggregate four /24s to a /22, suppress three, retain one exception, and inspect remote forwarding.

6. Palo Alto Networks — BGP Outbound Route Filtering (ORF)

Source: https://docs.paloaltonetworks.com/ngfw/networking/advanced-routing/create-bgp-routing-profiles

Beginner foundation — terms you need before this lesson

ORF lets a receiver tell a sender which prefixes it wants so unwanted NLRI need not be transmitted.

Why / mechanics / evidence

Capability negotiation → receiver communicates filter → sender filters before advertisement → receiver processes a smaller route set. Established BGP does not prove ORF was negotiated. Verify capabilities plus advertised/received route counts.

Lab

Permit one range via ORF and contrast the sender-side reduction with a conventional receiver-only inbound filter.

7. Fortinet — Graceful BGP Shutdown (RFC 8326)

Source: https://docs.fortinet.com/document/fortigate/8.0.0/administration-guide/86434

Beginner foundation — terms you need before this lesson

The gshut community marks planned maintenance; receivers lower LOCAL_PREF so traffic drains before session shutdown.

Why / mechanics / evidence

Mark routes → receiver de-preferences → alternate becomes best → traffic drains → optional delay → BGP session shuts. FortiOS documents persistent shutdown graceful|graceful-soft and one-time execute router clear bgp ... gshut. This is not graceful restart.

Lab

Use two exits, initiate gshut on one, verify LOCAL_PREF and traffic move before the peer is shut.

8. Fortinet — BGP Error Handling per RFC 7606

Source: https://docs.fortinet.com/document/fortigate/latest/administration-guide/573519/bgp-error-handling-per-rfc-7606

Beginner foundation — terms you need before this lesson

Malformed BGP attributes can trigger session reset, treat-as-withdraw, or attribute discard depending on severity.

Why / mechanics / evidence

UPDATE parse → identify malformed attribute → choose recovery severity → preserve healthy routes/session where safe. A peer staying Established while a bad route disappears can be correct RFC7606 behavior. Correlate neighbor state, logs and affected prefix.

Lab

Use a controlled test speaker to send malformed attributes and compare route-level versus session-level effects.

9. Fortinet — Preferred Source IP for Local-Out Traffic on BGP Routes

Source: https://docs.fortinet.com/document/fortigate/8.0.0/administration-guide/184807/defining-a-preferred-source-ip-for-local-out-egress-interfaces-on-bgp-routes-new

Beginner foundation — terms you need before this lesson

A BGP route can carry a preferred local source address for traffic originated by the FortiGate itself.

Why / mechanics / evidence

Route-map sets set-ip-prefsrc → BGP route records prefsrc → local-out packet uses stable loopback source → route forwards normally. Fortinet shows get router info bgp network and sniffer proof. Correct source selection still requires remote return reachability.

Lab

Use two destinations with two preferred loopback sources and verify packet source addresses via sniffer.

10. Arista — EVPN E-Tree

Source: https://www.arista.com/en/support/toi/tag/e-tree

Beginner foundation — terms you need before this lesson

E-Tree assigns Root and Leaf roles: roots can reach roots/leaves; leaves cannot directly reach leaves.

Why / mechanics / evidence

AC role → EVPN signaling/RT behavior → permitted remote import → forwarding enforces hub-and-spoke policy. A learned endpoint MAC does not necessarily imply leaf-to-leaf traffic is allowed. Verify attachment roles and route targets.

Lab

Build two leaf ACs and one root AC; prove both leaves reach root while lateral traffic remains blocked.

11. Arista — EVPN MAC Duplication Detection

Source: https://www.arista.com/en/support/toi/tag/mac-duplication

Beginner foundation — terms you need before this lesson

EVPN MAC mobility sequence numbers identify the newest endpoint location; repeated rapid moves can indicate duplicates or loops.

Why / mechanics / evidence

Competing Type-2 advertisements → mobility sequence chooses newest → repeated moves cross detection logic → unstable MAC can be suppressed. One legitimate VM move is not proof of duplication; frequency/history is the discriminator.

Lab

Perform one legitimate move, then create a duplicate MAC and compare sequence/suppression behavior.

12. Arista — EVPN MPLS VPWS

Source: https://www.arista.com/en/support/toi/tag/evpn-mpls

Beginner foundation — terms you need before this lesson

VPWS is a point-to-point Ethernet service signaled by BGP; it does not require customer MAC learning for forwarding.

Why / mechanics / evidence

Attachment circuit → EVPN VPWS service signaling → MPLS transport label/cross-connect → remote AC. An Up AC does not prove service signaling or transport. Do not troubleshoot by looking for tenant MAC Type-2 routes that are intentionally unnecessary.

Lab

Compare EVPN VPWS and a multipoint EVPN bridge, recording required control-plane objects.

13. FRRouting — MSDP with Anycast-RP

Source: https://docs.frrouting.org/en/latest/pim.html

Beginner foundation — terms you need before this lesson

MSDP exchanges Source-Active information between PIM-SM RPs; Anycast-RP lets multiple physical RPs share one service address.

Why / mechanics / evidence

Source register → local RP learns source → MSDP SA reaches peer RP → receiver-side RP can join toward source → PIM tree/mFIB forms. Verify RP mapping, MSDP peer/SA cache, RPF and receiver joins separately.

Lab

Use two anycast RPs, source near one and receiver near the other; remove MSDP while leaving unicast up.

14. FRRouting — OpenFabric / fabricd

Source: https://docs.frrouting.org/en/latest/fabricd.html

Beginner foundation — terms you need before this lesson

OpenFabric is IS-IS-derived link-state routing for fabric topologies; FRR implements it in fabricd and relies on zebra for interface/route integration.

Why / mechanics / evidence

zebra interface state → fabric adjacency/flooding → SPF → route candidates → zebra → kernel FIB. FRR notes that if zebra restarts, fabricd must also restart. Verify each boundary separately.

Lab

Build leaf-spine nodes and intentionally restart zebra to observe the integration dependency.

15. FRRouting — Babel Dual-Stack Routing

Source: https://docs.frrouting.org/en/stable-10.0/babeld.html

Beginner foundation — terms you need before this lesson

Babel is a loop-avoiding distance-vector IGP for wired/wireless mesh; one instance supports IPv4 and IPv6 and avoids RIP count-to-infinity.

Why / mechanics / evidence

Reachability/link quality exchange → feasibility rules → babeld best candidate → zebra → kernel FIB. Path changes may be caused by quality metrics without link-down. Verify Babel and zebra separately.

Lab

Vary path quality in a triangle and predict route movement before inspecting the tables.

16. Juniper — OSPF Loop-Free Alternates (LFA)

Source: https://www.juniper.net/documentation/us/en/software/junos/ospf/topics/topic-map/configuring-loop-free-alternate-routes-for-ospf.html

Beginner foundation — terms you need before this lesson

An LFA is a precomputed backup next hop that cannot loop traffic back through the protected failure. Junos can preinstall it in the PFE.

Why / mechanics / evidence

Primary SPF → backup SPF evaluates loop-free neighbors → qualifying backup installs in PFE → failure triggers local repair before global SPF. An alternate route is not automatically a valid LFA; topology determines coverage.

Lab

Compare triangle and ring topologies, determine which neighbors satisfy the LFA condition, then fail the primary link.

17. Juniper — BGP Accumulated IGP (AIGP)

Source: https://www.juniper.net/documentation/us/en/software/junos/cli-reference/topics/ref/statement/aigp-edit-protocols-bgp.html

Beginner foundation — terms you need before this lesson

AIGP carries accumulated interior cost in BGP for contiguous ASes under one administration.

Why / mechanics / evidence

IGP metric → AIGP attribute → BGP path selection can prefer lower accumulated internal cost across AS boundaries. Junos documents AIGP disabled by default and silently discarding received AIGP when not enabled. Inspect the path attribute itself.

Lab

Build equal-policy eBGP paths across internal AS boundaries with different AIGP totals and predict the winner.

18. Juniper — IS-IS Hello Padding and MTU Asymmetry Detection

Source: https://www.juniper.net/documentation/us/en/software/junos/cli-reference/topics/ref/statement/interface-edit-protocols-isis.html

Beginner foundation — terms you need before this lesson

IS-IS cannot fragment its PDUs; hello padding tests whether a link can support the packet size needed for reliable adjacency and database flooding.

Why / mechanics / evidence

Padded IIH → peer reception → adjacency advance → larger LSP flooding. hello-padding adaptive|loose|strict|disable changes how aggressively MTU compatibility is tested. Disabling padding can hide asymmetry until LSDB flooding fails.

Lab

Configure asymmetric MTUs and compare strict versus disabled padding, adjacency and LSDB behavior.

19. Aruba/HPE — DHCP Snooping Trusted/Untrusted Ports

Source: https://www.arubanetworks.com/techdocs/AOS-CX/10.13/PDF/ip_services_6200.pdf

Beginner foundation — terms you need before this lesson

DHCP snooping trusts legitimate server/uplink paths and treats client-facing ports as untrusted; server replies on untrusted ports are dropped and valid leases create bindings.

Why / mechanics / evidence

Client request → untrusted inspection → trusted server → OFFER/ACK returns trusted → binding learned. AOS-CX uses global/VLAN snooping, trusted interfaces, authorized servers and show dhcpv4-snooping. Mis-trusting either edge or server uplink causes security bypass or legitimate DHCP failure.

Lab

Attach a legitimate and rogue DHCP server to different trust classes and compare packet/binding outcomes.

20. Aruba/HPE — Loop Protect

Source: https://www.arubanetworks.com/techdocs/AOS-CX/10.13/PDF/l2_bridging_6300-6400.pdf

Beginner foundation — terms you need before this lesson

Loop Protect sends detection PDUs and reacts if its own probe returns, useful where STP is absent/ineffective or on selected edge/LAG/VXLAN contexts.

Why / mechanics / evidence

Probe → loop returns probe → configured action disables transmit or both directions (or just reports) → timers/counters record event. show loop-protect reveals counts and last detection. A disabled port can be an intentional protection result.

Lab

Create a controlled edge loop and compare tx-disable, tx-rx-disable and monitoring-only behavior.

21. Aruba/HPE — IP Source Lockdown

Source: https://developer.arubanetworks.com/new-central-config/reference/createipsourcelockdowninterfaceprofilebyid

Beginner foundation — terms you need before this lesson

IP Source Lockdown uses trusted address bindings to enforce which source IP/MAC combinations may transmit on an access interface.

Why / mechanics / evidence

DHCP/identity binding → lockdown profile attachment → hardware source-validation policy → spoofed/unbound traffic drop → normal routing only for permitted sources. A lease alone does not prove enforcement is attached to the right interface.

Lab

Learn a legitimate binding, enable lockdown, spoof another source address and verify hardware/drop evidence.

Multivendor normalization & troubleshooting tree

  1. Prove physical/LACP/transport/session state.
  2. Prove protocol-native route, service or endpoint state.
  3. Prove policy/capability/advertisement behavior.
  4. Prove global RIB ownership and recursion.
  5. Prove FIB/adjacency/tunnel/label/hardware programming.
  6. Prove actual packet egress, MTU, remote delivery and return path.

Translation rule: translate the state, not the literal command. Cisco CEF, PAN-OS Forwarding Table, FortiGate route/kernel state, EOS forwarding agent, FRR zebra/kernel, Junos PFE, and AOS-CX hardware all answer whether selected control intent became usable forwarding state.
