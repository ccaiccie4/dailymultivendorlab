Networking Foundations Primer

Universal dependency chain: originate/learn → policy → advertise/import → protocol candidate → global RIB ownership → recursion → FIB/adjacency/tunnel/label programming → packet delivery → return path.

Control plane vs data plane

The control plane learns and chooses routes, labels, memberships and endpoint locations. The data plane is the installed FIB, adjacency, tunnel, label or ASIC/kernel state that moves packets.

Route / prefix / next hop

A prefix names a destination range. A route is one candidate path. A next hop is the immediate or recursively resolved forwarding target.

RIB / FIB / adjacency

The RIB keeps candidates and selects a route. The FIB is forwarding-ready state. An adjacency is the final neighbor/tunnel/label relationship required to transmit.

Recursive next-hop resolution

A BGP or overlay next hop can point to another route, which can recurse again until a connected adjacency or tunnel is found.

Route origin / AD / preference

Origin says where a route came from. Administrative distance or Junos route preference chooses between route sources before internal best-path logic.

Underlay / overlay

The underlay provides infrastructure transport. VXLAN, EVPN, MPLS VPNs and other service overlays depend on it.

VXLAN / VTEP / VNI

VXLAN wraps tenant traffic in UDP/IP. VTEPs encapsulate/decapsulate. L2VNI identifies a bridge domain; L3VNI identifies tenant routing context.

EVPN / route types / RD / RT

EVPN uses BGP to signal endpoints and service reachability. RD makes VPN routes unique; RT controls import/export membership.

IRB / anycast gateway

IRB combines bridging and routing. Anycast gateway gives the same first-hop identity on multiple fabric nodes. Symmetric IRB commonly carries routed tenant traffic in an L3VNI.

BUM

Broadcast, unknown-unicast and multicast traffic requires replication or multicast delivery because there is no one known remote destination.

Redistribution / filters / tags

Redistribution re-originates routes between protocols. Prefix filters, communities, route maps and tags preserve policy and prevent feedback.

LACP / ESI / DF / multichassis

LACP bundles links. MLAG/vPC/VSX/MC-LAG coordinate chassis. EVPN multihoming identifies the Ethernet Segment with an ESI and elects a DF for selected BUM forwarding.

VRF / VLAN / trunk

A VRF is an isolated L3 table, a VLAN is an L2 broadcast domain, and a trunk carries multiple VLANs.

ASM / SSM / RPF

ASM lets a receiver ask for a group without naming the source and often uses an RP. SSM names source and group directly. RPF uses the unicast route back toward the source/RP.

1. Cisco Systems — OSPFv3 Prefix Suppression

Source: https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr3-fwd/ospf/ospf-configuration-guide/prefix-suppression-support-for-ospfv3.html
Classification/date: Official Cisco OSPF Configuration Guide — updated July 17, 2026

Beginner foundation — terms you need before this lesson

OSPFv3 separates topology from most address information. Router- and Network-LSAs describe graph connectivity, while Intra-Area-Prefix-LSAs carry many attached IPv4/IPv6 prefixes. Prefix suppression can remove selected locally configured transit prefixes without removing the graph edge itself.

Problem and why it exists

Reduce LSA scale, SPF work, flooding bandwidth and exposure of infrastructure-only addressing while retaining the topology needed to calculate paths.

Control-plane / packet-state story

A local interface participates in OSPFv3; the router originates topology state and separately decides whether its locally configured address prefix is eligible for suppression. Suppressed transit prefixes are omitted from prefix-bearing LSAs, while Router/Network-LSA connectivity remains. Remote routers can still compute a path through the link but no longer install a route to the hidden transit subnet.

Configuration and evidence teaching

Cisco documents global `prefix-suppression` under `router ospfv3` or an address family, plus interface-level suppression/disable overrides. `show ospfv3` asks whether the process has suppression enabled; `show ospfv3 interface` asks which interface overrides apply. The decisive proof is the remote LSDB/RIB: topology remains while the eligible transit prefix disappears.

Failure mechanism, prevention, design consequence and reproducible lab

Loopbacks, secondary addresses and passive-interface prefixes are documented exceptions to broad suppression. Do not confuse this with an arbitrary route filter. Lab: advertise a loopback plus transit /31, enable global suppression, compare remote LSDB/RIB, then use an interface override.

Multivendor / standards implication

The durable engineering question is not the vendor command name but the state transition this feature controls. Translate the mechanism into its standards-level role, then find the equivalent control-plane object, RIB/FIB dependency and packet evidence on the other six platforms. Do not assume identical defaults, timers, policy-attachment points or failure actions.

2. Cisco Systems — EIGRP Wide Metrics and RIB Scaling

Source: https://www.cisco.com/c/en/us/td/docs/routers/ios-xe/ip-routing/b-ip-routing/m_ire-wid-met.html
Classification/date: Official Cisco IOS XE IP Routing Guide — current 2026 publication

Beginner foundation — terms you need before this lesson

Classic EIGRP metric arithmetic loses useful resolution on modern high-speed interfaces. Wide Metrics use 64-bit calculations in named mode, with finer throughput and latency scaling and support for very high-speed links and bundles.

Problem and why it exists

Preserve meaningful path differentiation on 10/40/100/400G and large EtherChannels where old formulas can make distinct paths look equivalent.

Control-plane / packet-state story

Interface bandwidth and delay feed the wide composite formula. Named EIGRP calculates the 64-bit metric, DUAL selects a successor/feasible alternatives, and a RIB scaling factor maps the larger internal value into the route table representation. The FIB then programs the selected path.

Configuration and evidence teaching

Verify named mode and K values before comparing metrics. Cisco documents `metric rib-scale`; changing it clears and reinstalls EIGRP routes in the RIB with newly scaled values. An Up neighbor proves adjacency, not that the metric formula has enough resolution to rank high-speed paths.

Failure mechanism, prevention, design consequence and reproducible lab

K-value mismatch can prevent adjacency; poor RIB scaling can collapse distinct EIGRP metrics after protocol selection. Lab: create two high-speed paths with small latency differences, compare named wide metrics and RIB-scaled values.

3. Cisco Systems — BGP Route Flap Dampening Penalty and Reuse

Source: https://www.cisco.com/c/en/us/td/docs/routers/ios-xe/ip-routing/b-ip-routing/m_irg-int-features-0.html
Classification/date: Official Cisco IOS XE BGP Configuration Guide — current 2026 publication

Beginner foundation — terms you need before this lesson

Dampening assigns an instability penalty to a route. Repeated withdrawal/re-advertisement raises the penalty. Crossing the suppress threshold hides the route; decay eventually lowers the penalty below the reuse threshold.

Problem and why it exists

Contain a repeatedly unstable external route so it does not force endless UPDATE/withdraw propagation and downstream reconvergence.

Control-plane / packet-state story

A prefix flaps, receives penalty and enters history state. Penalties accumulate. When suppression threshold is crossed, BGP stops advertising/using the route even if it reappears. The penalty decays according to half-life. When it falls below reuse, the route becomes eligible again; max-suppress bounds how long it can stay hidden.

Configuration and evidence teaching

Cisco documents `bgp dampening ...`, `show ip bgp dampening flap-statistics`, and `show ip bgp dampening dampened-paths`. These commands answer whether the route is in history/damped state, its penalty and reuse time. A peer reset itself withdraws routes but does not add a dampening penalty.

Failure mechanism, prevention, design consequence and reproducible lab

Over-aggressive dampening can hide legitimate rapidly recovering destinations. Lab: flap one eBGP prefix repeatedly, observe history→damped→reuse transitions, then reset the peer and compare penalty behavior.

4. Palo Alto Networks — PIM Source-Specific Multicast

Source: https://docs.paloaltonetworks.com/ngfw/networking/ip-multicast/pim
Classification/date: Official Palo Alto Networks multicast documentation — current 2026

Beginner foundation — terms you need before this lesson

SSM is multicast where the receiver requests a specific source and group, (S,G). Unlike Any-Source Multicast, true SSM does not need an RP for source discovery. Receiver signaling normally uses IGMPv3 so the source address can be named.

Problem and why it exists

Remove RP/source-discovery complexity for applications that know the sender and want only that sender’s traffic.

Control-plane / packet-state story

The host sends an IGMPv3 source-specific membership report. The receiver-facing firewall creates (S,G) state and sends a PIM Join toward the source according to unicast RPF. Intermediate routers install (S,G) state and the source stream follows the source tree.

Configuration and evidence teaching

Verify PIM on receiver-facing interfaces, IGMPv3 membership, the SSM group range and the unicast route used for RPF toward S. A healthy RP mapping is not evidence for SSM because RP discovery is not in the path.

Failure mechanism, prevention, design consequence and reproducible lab

IGMPv2/group-only signaling or a group outside the SSM range can defeat the intended model. Lab: use a 232/8 group with IGMPv3, then change group/version and compare (S,G) state.

PAN-OS Advanced Routing exposes suppress/reuse limits, maximum hold time, and separate reachable/unreachable decay half-lives in a BGP Dampening Profile.

Control-plane / packet-state story

6. Palo Alto Networks — OSPF Area Range Summarization and Suppression

Source: https://docs.paloaltonetworks.com/ngfw/networking/ospf/configure-ospf
Classification/date: Official Palo Alto Networks OSPF documentation — current 2026

Beginner foundation — terms you need before this lesson

An OSPF ABR summarizes intra-area routes into inter-area reachability. PAN-OS Area Range can advertise an aggregate or suppress matching inter-area advertisement by disabling Advertise.

Problem and why it exists

Reduce inter-area LSA scale and hide internal addressing details at the area boundary.

Control-plane / packet-state story

Specific routes exist in the source area. The ABR matches them against the configured Area Range. With Advertise enabled it originates a summary into other areas; with Advertise disabled it suppresses the matching inter-area advertisement. Remote routers calculate routes from the ABR-generated state.

Configuration and evidence teaching

Inspect the exact range/mask, Advertise setting and resulting LSDB on another area. Area Range is not the same as external-route summarization, which is a separate OSPF control.

After reboot, an MLAG peer needs time to rebuild control-plane and hardware forwarding state. Reload delay intentionally holds MLAG/non-MLAG links down during that window.

Control-plane / packet-state story

Source: https://docs.frrouting.org/en/latest/bgp.html
Classification/date: Official FRRouting documentation — current 2026

Beginner foundation — terms you need before this lesson

RFC 8092 Large Communities use three 32-bit values: Global Administrator and two local-data fields. They avoid classic community limitations with 32-bit ASNs and provide structured policy metadata.

Problem and why it exists

Carry scalable routing policy metadata across modern BGP deployments.

Control-plane / packet-state story

UPDATE carries Large Community values. bgpd stores canonical ordered attributes. A large-community-list or route-map matches the entire string/set; route-map actions may overwrite or add values. Export sends the resulting attribute to the next peer.

Configuration and evidence teaching

FRR documents `show bgp large-community-list`, `show ip bgp large-community-info`, `match large-community ... [exact-match]`, and `set large-community ... [additive]`. Without `additive`, set replaces existing values.

Failure mechanism, prevention, design consequence and reproducible lab

Expanded large-community lists are for matching, not setting. Lab: add two values, use non-additive set, then additive set, and compare the exported attribute.

Multivendor / standards implication

The durable engineering question is not the vendor command name but the state transition this feature controls. Translate the mechanism into its standards-level role, then find the equivalent control-plane object, RIB/FIB dependency and packet evidence on the other six platforms. Classification/date: Official Juniper Multiprotocol BGP documentation — current 2026

Beginner foundation — terms you need before this lesson

`prefix-limit` counts received prefixes before import policy; `accepted-prefix-limit` counts routes that survive policy. Newer Junos can teardown, drop-excess or hide-excess depending on the option.

Problem and why it exists

Protect memory/control-plane scale at the exact stage that matters: raw peer input versus accepted RIB candidates.

Control-plane / packet-state story

Peer sends NLRI. The received counter is checked against prefix-limit. Import policy accepts/rejects. Accepted counter is checked against accepted-prefix-limit. The configured action then logs, tears down, drops or hides excess routes.

Configuration and evidence teaching

`show bgp neighbor` exposes relevant counts and newer dropped/hidden state. Use raw received limits when the peer itself is the scale risk; use accepted limit when policy-filtered scale is the concern.

Failure mechanism, prevention, design consequence and reproducible lab

A raw limit can reset a peer that sends many routes even if policy discards most. Lab: send 1,000 routes, accept 50, and compare both counters/actions.

Fast periodic is about one LACPDU per second; slow is about every 30 seconds. Actor and partner advertise timeout expectations, and the transmitter honors the receiver’s requested rate.

Problem and why it exists

Choose a convergence/control-overhead tradeoff appropriate to critical aggregated links.

Control-plane / packet-state story

Each side advertises LACP actor/partner state including timeout preference. The peer transmits according to the receiver’s requested cadence. Eligible members reach collecting/distributing; protocol timeout can remove a failed member before upper-layer protocols react.

Configuration and evidence teaching

Configure `periodic fast|slow` under aggregated Ethernet LACP and inspect both actor and partner state. Local configuration alone is not proof of effective negotiated cadence.

Failure mechanism, prevention, design consequence and reproducible lab

Fast/slow mismatch does not mean each side blindly transmits at its own interval. Lab: mismatch settings and capture LACPDUs to measure actual behavior.

A VSF stack can partition into independent fragments after enough VSF link failures. Split detection provides an independent way for fragments to discover each other and suppress one side.

Problem and why it exists

Prevent split-brain duplicate forwarding when conductor and standby end up in separate active fragments.

Control-plane / packet-state story

A VSF link failure partitions the stack. Each fragment has role state. Split-detect connectivity reveals the competing fragment. The fragment with the primary stays active; the other shuts non-VSF front-plane interfaces. Reconnection restores one stack.

Configuration and evidence teaching

Verify ring/chain topology, conductor/standby placement and split-detect path. A ring degrading to one connected chain is not yet a split brain.

Failure mechanism, prevention, design consequence and reproducible lab

Without split detection, conductor and promoted standby fragments can both forward. Lab: split a four-member stack with conductor/standby separated and compare front-plane state with split detection.

21. Aruba/HPE — OSPF Passive Interface Semantics

Source: https://www.arubanetworks.com/techdocs/AOS-CX/10.13/PDF/ip_route_8400.pdf
Classification/date: Official Aruba AOS-CX IP Routing Guide — 10.13

Beginner foundation — terms you need before this lesson

A passive OSPF interface stays in the OSPF process and its connected network can still be advertised, but it sends/receives no OSPF packets and forms no adjacency on that interface.

Problem and why it exists

Advertise user/loopback subnets without accidental neighbors or unnecessary Hello traffic on endpoint-facing VLANs.

Control-plane / packet-state story

The interface is placed in an area and contributes its connected prefix. `ip ospf passive` suppresses Hello/DD/LSR/LSU adjacency exchange on that link. Other routers can still learn the subnet through the originating router’s LSAs.

Configuration and evidence teaching

Verify the interface is passive and verify the prefix appears remotely. No neighbor on a passive interface is expected; on a transit link it is a configuration error.

Failure mechanism, prevention, design consequence and reproducible lab

Making an inter-router transit interface passive prevents adjacency. Lab: compare desired passive user SVI with an accidentally passive routed inter-switch VLAN.
